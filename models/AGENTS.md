# 模型架构图交付约定

- 每张作为正式架构图交付的 PNG 必须有同名原生可编辑 `.drawio` 支撑。PNG 必须直接由该 draw.io 导出，不能让图像生成工具另画一份计算结构。
- 新图先核对配置、模型实现和报告，记录来源及不确定项，再创建 draw.io 节点与连线。默认按自下而上推理顺序组织，展开注意力控制分支、门控、残差和 MoE 路由。
- 从已有 PNG 转换时，逐节点、逐连线重建并保留原 PNG 供对照。不能以嵌入整张位图冒充可编辑转换，也不能将人工重建称为像素无损恢复。
- 使用 `tools/model_architecture/model_architecture.py export-png` 从 XML 导出，并保存 `.export.json`；交付前运行 `verify-png`。导出记录验证文件配对，不能替代架构语义核对。
- 修改 draw.io 后重新导出 PNG，不可单独修补正式 PNG。图像生成只允许用于单独命名的非正式风格参考，不得覆盖配对产物。
- 当前工具仅测试标准未压缩 draw.io / mxGraph XML，飞书客户端的导入效果不能在未实际验证时声称已通过。

- 正式导出必须通过实测布局检查：文字不越界且有安全留白，连线为对齐的正交线段，不穿过无关运算节点。保留 `.layout.json` 并纳入配对校验。

## 后续模型绘图

- 新模型或版本差异图先阅读 [统一绘图规范](../tools/model_architecture/WORKFLOW.md)，可使用 `model_architecture.py init-study` 建立待审阅模板。
- 节点用简短算子和必要维度，长说明移入description／证据文档；字体分层、主链对齐。连线优先无障碍直线、其次单直角，不能为减少折点删除计算边。
- 版本差异统一为红新增、绿退役、黄参数／配置，中性表示共享与旧图澄清。绿色退役项不接入当前推理；仅配置字段删除不等于网络删除。
- 区分本版新增、继承设计与后端实现；位宽、缓存、top-k及性能口径不得混淆。交付前同时审阅实际缩略图和放大细节。

- 节点尺寸须按算子视觉复杂度、名称长度、必要维度及分支接口分别判断；前后节点保持主轴对齐，并行投影保持同一层级。用合适宽高和换行提高可理解性，避免所有框等宽等高或仅靠缩小字体容纳文字。

- 新图和后续修改统一执行[12条默认绘图规则](../tools/model_architecture/DRAWING_RULES.md)：白色画布、分组无填充、重复结构矩形框左上角×N、输入输出维度标在实际连线上、紧凑排版；其余来源、视图、同源与实测检查要求同样适用。
